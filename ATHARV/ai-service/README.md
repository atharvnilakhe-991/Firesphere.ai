The **FireSphere AI Service** is an internal microservice providing automated Computer Vision, AI-assisted safety inspection analysis, and auditable inspection report drafting for fire administration. It powers evidence-linked defect detection, deterministic severity evaluation, operational risk scoring, evidence-grounded explainability, and deterministic report draft compilation for inspecting fire safety officers.

> [!IMPORTANT]
> **Strict Governance & Regulatory Safety Rule:**
> 1. The inspection report draft generated by the AI service is an **advisory draft for an authorized human Fire Safety Officer**.
> 2. The AI service **NEVER autonomously approves or rejects a Fire NOC (No Objection Certificate)**.
> 3. AI outputs do **NOT constitute a statutory or legal compliance decision**. Forbidden compliance states (`AI_APPROVED`, `AI_REJECTED`, `AI_NOC_APPROVED`, `AI_NOC_REJECTED`) are blocked by programmatic schema validators.
> 4. The AI system **NEVER fabricates fire safety regulations, code numbers, acts, penalties, statutory deadlines, building dimensions, water tank capacities, or unobserved site facts**.
> 5. The AI service uses **ZERO external proprietary LLMs** and operates deterministically.

## 1. System Architecture

```mermaid
graph TD
    Mobile[FireSphere Mobile App / React Native] -->|Uploads Evidence Photographs| SpringBoot[Spring Boot Core Backend]
    SpringBoot -->|Persists Evidence Bytes & SHA-256| Storage[(MinIO / S3 Object Storage)]
    SpringBoot -->|Dispatches Job: POST /internal/ai/jobs| FastAPI[FastAPI AI Service (API Mode)]
    FastAPI -->|Enqueues Job ID to FIFO List| Redis[(Redis Job Queue)]
    FastAPI -->>|Returns HTTP 202 Accepted| SpringBoot
    
    subgraph Asynchronous Worker Tier
        Worker[AI Worker (Worker Mode: app.worker)] -->|BRPOP Dequeues Job| Redis
        Worker -->|Downloads & Verifies SHA-256| Storage
        Worker --> Validate[File & Content Signature Validation]
        Validate --> Decode[OpenCV Image Decode]
        Decode --> Quality[Image Quality & Blur Validation]
        Quality --> Letterbox[Aspect-Ratio Preserving Letterbox]
        Letterbox --> Norm[RGB Normalization float32]
        Norm --> Tensor[Tensor Ingestion 1, 3, 640, 640]
        Tensor --> ModelRunner[PyTorch CV Model Runner / YOLO Adapter]
        ModelRunner --> NMS[Non-Maximum Suppression & Threshold Filter]
        NMS --> BBoxTransform[Letterbox to Original Coordinate Projection]
        BBoxTransform --> IntelLayer[Phase 4 Intelligence Layer]
        IntelLayer --> FindingMapper[Confidence, Severity, Risk & Explainability]
        FindingMapper --> ReportDraft[Phase 5 Deterministic Report Draft]
        ReportDraft --> UpdateState[Updates Job Status: COMPLETED]
        UpdateState --> Redis
    end

    SpringBoot -->|Polls: GET /internal/ai/jobs/{id}/result| FastAPI
    FastAPI -->|Retrieves Completed Draft| Redis
    FastAPI -->>|Returns Findings & Advisory Draft| SpringBoot
    SpringBoot --> Officer[Fire Safety Officer Review & Physical Verification]
```

### Responsibility Boundary
* **Member 4 (AI/ML & CV)**: FastAPI AI Service, async worker daemon, job contracts, secure evidence retrieval, OpenCV image validation/preprocessing, tensor preparation, model inference adapter, Non-Maximum Suppression (NMS), coordinate projection, confidence calibration, deterministic severity engine, context-aware operational risk scoring, evidence-grounded explainability (WHAT, WHERE, CONFIDENCE, WHY, VERIFY), officer verification checklists, executive inspection summary, deterministic report generation, dataset hygiene tooling, model training/evaluation harnesses, and failure isolation.
* **Backend (Spring Boot)**: NOC workflow orchestration, authentication/authorization, business rules, job dispatching, officer review persistence, and statutory NOC issuance.
* **Mobile (React Native)**: Field evidence capture, UI display of officer review and advisory findings.

## 3. Model Decision Gate & Governance (Case C)

A thorough repository and environment audit was conducted prior to implementation:
1. **Model Weights**: None pre-existed in repository (`.pt`, `.pth`, `.onnx`).
2. **Dataset**: No annotated fire safety inspection dataset pre-existed in repository.
3. **Hardware**: Host environment possesses an **NVIDIA GeForce RTX 4050 Laptop GPU (6141 MiB VRAM)**, Driver 592.82, CUDA 13.1. Automatic CPU fallback is fully operational.
4. **Resolution (Case C — Truth in AI)**:
   * **Zero Fabricated Detections**: Generic models (e.g., COCO 80 classes) are **not** substituted, as they do not possess verified capability for fire compliance defects.
   * **Classification**: Formal system status is `INFRASTRUCTURE_READY_MODEL_PENDING`.
   * **Full Model Architecture Implemented**: Tensor ingestion $(1, 3, 640, 640)$, Non-Maximum Suppression (NMS), coordinate projection back to original photographs, dataset validator, model trainer, comprehensive evaluator, ECE calibration engine, and model registry are fully implemented and verified.
   * Detailed model and dataset status is documented in [ai-service/docs/phase7-model-readiness.md](file:///c:/Users/athar/OneDrive/Desktop/Firesphere.ai/ai-service/docs/phase7-model-readiness.md).

## 5. Model Ingestion & Coordinate Projection

```
Preprocessed Image (640, 640, 3, RGB, float32)
       ↓
[CVModelAdapter.prepare_input_tensor]
       ↓ Transpose (H,W,C) -> (C,H,W) and add batch dim
Input Tensor: (1, 3, 640, 640)
       ↓
Model Forward Pass / Inference
       ↓
[Non-Maximum Suppression] (IoU threshold 0.45)
       ↓
[Confidence Threshold Filtering] (score >= 0.50)
       ↓
[BoundingBoxTransformer.letterbox_to_original]
       ↓ Un-pad and un-scale coordinates
Finding Bounding Box: normalized [0.0, 1.0] on original photograph
```
